# PART 6 — Observability Stack

## What was built (all under `deploy/observability/`)
- `prometheus/prometheus.yml` — scrape/eval 5s; jobs `pulseops-api` (`pulseops-api:8000`), `postgres` (`postgres-exporter:9187`), `prometheus`; rule file `/etc/prometheus/alerts.yml`.
- `prometheus/alerts.yml` — the five Contract 4.10 alerts (names, `for`, thresholds), each with `severity` label and `summary`/`description` annotations.
- `grafana/provisioning/datasources/datasources.yml` — Prometheus (default, uid `prometheus`) and Jaeger (uid `jaeger`).
- `grafana/provisioning/dashboards/dashboards.yml` — file provider reading `/var/lib/grafana/dashboards`.
- `grafana/dashboards/service-health.json` — uid `pulseops-service-health`, title "PulseOps - Service Health": request rate by route, error ratio, latency p50/p95/p99, in-progress, alert state table, process CPU.
- `grafana/dashboards/db-and-pool.json` — uid `pulseops-db-pool`, title "PulseOps - DB & Pool": pool checked out vs size, checkout wait p95, query p95 by operation, PG connections, transactions/s, rows fetched/returned.
- Both dashboards: refresh 5s, range `now-15m`, built-in "Annotations & Alerts" on, plus an annotation query on tag `pulseops`.

## How it was verified (real results)
- `promtool check rules alerts.yml` (promtool v2.54.1): `SUCCESS: 5 rules found`.
- `promtool check config` on prometheus.yml (rule path rewritten to a local copy of alerts.yml for the check): valid.
- All four YAML files parse with PyYAML; both dashboard JSONs parse.
- A script confirmed the alert expressions reference only Contract metrics (`http_request_duration_seconds`, `http_requests_total`, `db_pool_*`, `db_query_duration_seconds`, `up`), and that dashboard panels use only Contract metrics plus `process_cpu_seconds_total`, `ALERTS` and `pg_stat_database_*`.

## NOT verified

- The `pg_stat_database_*` metric names come from postgres-exporter's `stat_database` collector (on by default). I did not run the exporter, so confirm they appear in Prometheus.

## Decisions / things Part 1 and Part 9 should know
- Container paths are not fixed by the Contract, so I assumed: Prometheus config dir mounted at `/etc/prometheus` (rule path `/etc/prometheus/alerts.yml`); Grafana provisioning at `/etc/grafana/provisioning`; dashboards mounted at `/var/lib/grafana/dashboards`. Part 1's compose mounts must match these.
- The "alert state list" is a table panel over `ALERTS` rather than Grafana's alertlist panel, because there is no Alertmanager and alertlist is aimed at Grafana-managed alerts.
- Annotations posted by the CLI carry no dashboard id, so the built-in dashboard annotation would not show them. That is why each dashboard also has a tag query for `pulseops`.
- The error-ratio and latency expressions return nothing when there is no traffic, so alerts stay quiet at idle.
